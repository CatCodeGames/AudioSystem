# План WebGL-демо AudioSystem

Статус: предложение к реализации. Создан 24.11.2026. Этот документ не означает, что сцена или WebGL-билд уже сделаны.

## Цель и ограничения

За 30–60 секунд посетитель должен услышать и понять три достоинства: Pause/Mute по иерархии групп, безопасный AudioHandle, завершение через callback или await. Вся структура, маршруты, значения и результаты видны в браузере; открывать Unity и README не требуется.

Одна сцена `Assets/Example/Scenes/Example.unity`, один экран, uGUI + TMP, существующие AudioService и UniTask. Desktop WebGL — основной формат; узкое окно поддерживается прокруткой. Реализация демо остаётся в `Assets/Example`, runtime пакета не получает зависимостей от интерфейса.

## Вид экрана

```text
AudioSystem                                      [Стоп всё] [Сброс]
Управляйте звуками и целыми ветками микшера.
┌─ Группы микшера ───────────┬─ Звуки ────────────────────────────────┐
│ Master                    │ Музыка → Master/Music                  │
│ ├─ Music                  │ Играет  [Пауза] [Стоп]   Loop: вкл     │
│ └─ SFX                    │ Громкость 40% ━━━  Pitch 1.00× ━━━    │
│    ├─ World               │                                        │
│    └─ UI                  │ Эффект → Master/SFX/World              │
│                           │ Играет  [Пауза] [Стоп]   Loop: вкл     │
│ Каждая строка:            │ Громкость 25% ━━━  Pitch 1.00× ━━━    │
│ [Пауза] [Mute] Громк. 80% │                                        │
│ Итог: пауза от Master/SFX │ Сигнал → Master/SFX/UI   [OneShot]     │
│                           │ Громкость 50% · короткий звук           │
├───────────────────────────┴────────────────────────────────────────┤
│ [Показать наследование] [Async: завершение] [Async: отмена]         │
│ [Проверить старый handle]   Результат: Completed / Interrupted    │
│ Подсказка: поставьте SFX на паузу — музыка продолжит играть.       │
└────────────────────────────────────────────────────────────────────┘
Управляемые воспроизведения: 2 · Пул AudioSource: занято 2 / создано 8
```

- Основа 1280×720: поля 24 px, промежутки 16 px, шапка 64 px, дерево около 340 px, остальное — звуки; нижняя зона сценариев около 100 px. CanvasScaler: Scale With Screen Size, Match 0.5.
- Фон `#101416`, панели `#192024`, текст `#E7ECEF`, вторичный текст `#A9B4BC`. Один акцент `#62D6BC`; жёлтый для паузы. Разделители 1 px, скругления до 6 px, без теней, градиентов, 3D и декоративных анимаций.
- Основной шрифт 18–20 px, заголовок 28 px, вторичные подписи минимум 16 px; числа можно выделить имеющимся моноширинным шрифтом. Кнопки от 40 px по высоте.
- Состояние обозначается текстом и цветом: «Играет», «Пауза звука», «Пауза группы», «Завершён». Mute показывается отдельно: звук может продолжать играть без слышимого вывода.
- До первого взаимодействия — экран с одной кнопкой «Включить звук и начать», подсказкой о громкости и ссылкой на исходники. После нажатия запускается музыка на 40%; эффект запускается отдельно. При неудаче запуска показывается повторная кнопка и понятное сообщение.
- При ширине окна менее 1000 px панели идут вертикально; весь контент доступен прокруткой, дерево остаётся раскрытым. Веб-оболочка содержит загрузку, ошибку запуска, fullscreen и ссылку на GitHub; технические параметры сборки на основной экран не выводятся.

## Поведение и данные

| Область | Конкретное поведение |
|---|---|
| Дерево | Реальный микшер `Master → Music, SFX → World, UI`. Названия, вложенность и полные маршруты видны постоянно. UI связан с реальными AudioMixerGroup; Pause/Mute читаются из mirror, не вычисляются второй моделью в демо. |
| Pause/Mute | Переключатели меняют LocalValue. Рядом отдельная подпись TotalValue и причины: «локально», «от SFX», «локально и от SFX». Наследование не изменяет положение локального переключателя; пользователь может заранее задать локальное значение под паузой родителя. |
| Громкость групп | 0–100%, изначально 100%; exposed-параметры `MasterVolume`, `MusicVolume`, `SfxVolume`, `WorldVolume`, `UiVolume`. Перевод в dB, при нуле −80 dB. Подпись «локальная громкость группы»; влияние родителей видно по дереву и слышно. |
| Музыка | `Music 1.wav`, группа Music, Loop включён, громкость 40%, Pitch 1.00×. Play / Pause или Resume / Stop; числовые значения обновляются при движении слайдеров. |
| Эффект | `Effect 1.wav`, группа World, Loop изначально выключен, громкость 25%, Pitch 1.00×. Те же команды; callback сохраняет видимый итог Completed или Interrupted. Для показа наследования включается Loop. |
| Общие настройки звука | Volume 0–100%, Pitch 0.5–2.0×. Изменения применяются к текущему хендлу и следующему запуску. Loop изменяется во время воспроизведения; Play недоступен, пока звук активен. |
| OneShot | `Effect 2.wav`, группа UI, громкость 50%. Повторные нажатия допускают наложение. При паузе UI/SFX/Master показывается «Пропущен: группа на паузе»; очередь не создаётся. При Mute показывается «Запущен без звука: Mute». Не рисовать фиктивный хендл и результат завершения. |
| Стоп всё | Прерывает активный сценарий, останавливает все звуки, оставляет настройки групп и слайдеров. Результаты Interrupted остаются видны. |
| Сброс | Отменяет сценарий, останавливает звуки, очищает итоги, снимает локальные Pause/Mute и возвращает значения по умолчанию. Остаётся тишина; повторный запуск — кнопкой Play. |
| Диагностика | Реальные данные GetInfo с обновлением 5 раз/с. Явно подписать, что счётчики относятся к управляемым воспроизведениям и их пулу; OneShot в них не входит. Не заявлять измеренные 0 GC по этим числам. |

Звуки использовать локально, без сетевой загрузки. Перед финалом прослушать существующие WAV: музыка должна иметь приемлемый стык, зацикленный эффект — не раздражать. При необходимости сделать отдельный демонстрационный loop с паузой между ударами; источник и право распространения зафиксировать. Индикация «Играет» отражает состояние воспроизведения, а не измеренную амплитуду: фальшивый VU-метр не нужен.

## Четыре проверки достоинств

Каждая кнопка сначала явно сообщает «Настройки будут сброшены», затем при самом нажатии восстанавливает исходные значения и начинает один сценарий. Одновременно работает один сценарий; остальные кнопки и ручные настройки временно недоступны. «Стоп всё» и «Сброс» доступны всегда. По завершении ручное управление возвращается. Ожидания интерфейса используют реальное время.

1. **Наследование, около 12 секунд.** Музыка и зацикленный эффект → через 3 с Pause SFX → подсветить World и UI с подписью «Пауза от SFX», музыка продолжает играть → нажатие OneShot во время паузы демонстрируется подписью о пропуске → через 3 с Resume SFX → через 2 с Mute SFX → через 2 с снять Mute. Музыка и эффект остаются доступны для ручных опытов. Дополнительная строка поясняет: Pause сохраняет позицию, Mute сохраняет ход воспроизведения.
2. **Async: завершение.** Один конечный запуск эффекта через PlayAsync, Loop выключен. Видно «Ожидание…» и затем реальный `Completed`; хендл после результата невалиден. Результат не заменяется заранее заданной надписью.
3. **Async: отмена.** PlayAsync эффекта с Loop; через 0.7 с отменить его токен. Видно `Interrupted`, звук остановлен, операция завершена без исключения отмены. Токен принадлежит этому запуску и освобождается после await. Обе async-проверки используют строку эффекта, а не скрытый источник.
4. **Старый handle.** Запустить A, сохранить хендл, остановить A, запустить B с Loop. Вызвать Stop и установить Volume = 0 через старый хендл A. Проверить и вывести: `A.IsValid = false`, `B.IsValid = true`, громкость B не изменилась. B продолжает звучать; успех показывается только по фактическим проверкам. Внутренние идентификаторы пула на экран не нужны.

Под результатом каждой проверки — одна короткая строка API, например `await service.PlayAsync(..., out handle, token)` или `mirror.Pause.SetValue(true)`. Без редактора кода и длинной справки. Ошибка проверки отображается как ошибка с причиной, а не как успешная демонстрация.

## Владение и структура

```text
DemoController → DemoView
               → AudioService → AudioHandle / AudioMixerGroupMirror
               → UniTask, UniLoop
```

| Компонент | Отвечает за | Не знает |
|---|---|---|
| `DemoController` | Команды UI, хендлы двух строк, результат каждого запуска, сценарий и его токен, подписки mirror, обновление диагностики. Вызывает AudioService напрямую. | Вёрстку и детали пула внутри пакета. |
| `DemoView` | Сериализованные ссылки на элементы, отображение переданных состояний, доступность кнопок, адаптивную компоновку. | AudioService, наследование Pause/Mute, правила сценариев. |
| AudioService | Реальное воспроизведение, иерархическое состояние, завершение и пул. | Демосцену и пользовательские подсказки. |

Данные — сериализованные записи групп и звуков в DemoController: AudioMixerGroup, родитель для отображения, exposed-параметр, AudioClip, значения по умолчанию. Это описание фиксированной демонстрационной иерархии; соответствие микшеру проверяется при подготовке сцены. Не восстанавливать дерево по именам в UI и не дублировать его расчёт состояний.

Минимальные новые команды: `StartDemo()`, `RunScenario(Scenario)`, `StopAll()`, `ResetDemo()`. Ручные команды используют индекс строки и прямой вызов контроллера. Контроллер подключает UI-обработчики и подписки; при уничтожении сначала запрещает новые сценарии, снимает обработчики и подписки, затем прекращает принадлежащие ему операции. Callback/await проверяет актуальность запуска перед изменением UI. Для простого callback передаётся узкая запись строки; `this` нужен только сценарию, действительно использующему роль контроллера.

## WebGL и критерии готовности

- Удалить зависимость демонстрации от Pitch микшера и Time.timeScale. Групповая громкость — через AudioMixer.SetFloat; Pitch отдельных звуков — через AudioHandle с положительным диапазоном. В Web у микшера поддерживается изменение громкости, остальные параметры не поддерживаются: [Unity 6.6 Audio in Web](https://docs.unity.com/en-us/engine/6000.6/manual/platform-specific/webgl/develop/audio).
- Начальные параметры доставки: Gzip + Decompression Fallback для хостинга без настройки Content-Encoding, WebGL 2, потоки выключены, Development Build выключен. Fallback увеличивает загрузчик и отключает streaming-компиляцию WASM; после замера менять только при реальной необходимости. [Unity: Deploy a Web application](https://docs.unity.com/en-us/engine/6000.6/manual/platform-specific/webgl/building-distribution/deploying).
- Проверить опубликованный адрес с подпутём `/AudioSystem/`, относительные ссылки на Build/TemplateData, холодную загрузку, повторное открытие, fullscreen и возвращение из фоновой вкладки. Загрузка или ошибка не должны оставлять пустой canvas.
- При возврате из фоновой вкладки UI перечитывает реальное состояние; если браузер приостановил аудио, доступна кнопка возобновления через пользовательское нажатие. Не обещать воспроизведение в фоне.
- Браузеры: актуальные Chrome/Edge и Firefox; Safari — при доступном устройстве. Зафиксировать фактически проверенные версии и непроверенные случаи. На широком экране и в окнах 960×600 / 390×844 нет обрезанных элементов и недоступных кнопок.
- Ручная проверка: Pause/Mute на каждом уровне; локальное значение под родительским; изменение Volume/Pitch/Loop во время звука; Completed/Interrupted; OneShot под Pause/Mute; старый хендл; Stop/Reset во всех сценариях. Консоль браузера без необработанных исключений.
- Не заявлять allocation-free по демо UI: интерфейс и TMP могут выделять память. Утверждение про прогретый runtime требует отдельного измерения, вне этой сцены.
